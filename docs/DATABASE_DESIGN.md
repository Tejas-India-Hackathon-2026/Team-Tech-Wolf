# AGRO-SMART Database & Data Architecture

**Relational Schema Design, Dual-Mode Storage & Data Flow Specifications**

---

## 1. Database Overview

AGRO-SMART features a **dual-mode data architecture**:
1. **Production-Ready Relational Layer**: Defined in [`database/schema.sql`](file:///c:/Users/preeb/agro%20smart%20tejas%20hackathon/database/schema.sql) and seeded via [`database/seed.sql`](file:///c:/Users/preeb/agro%20smart%20tejas%20hackathon/database/seed.sql), designed for PostgreSQL (hosted on Supabase).
2. **Local / Demo In-Memory Storage**: Built into the backend service layer (`backend/services/`), providing instantaneous, self-contained data operations during hackathons and offline demonstrations without requiring an active cloud database connection.

---

## 2. Existing Tables & Core Data Models

The relational schema specifies 6 primary tables:

```text
┌─────────────────────────────────────────────────────────────┐

│  - state, district, status, created_at                      │
└──────────────┬──────────────────────────────┬───────────────┘
               │ 1:N                          │ 1:N
               ▼                              ▼
┌─────────────────────────────┐ ┌─────────────────────────────┐
│        disease_scans        │ │          machinery          │
│  - id (UUID PK)             │ │  - id (UUID PK)             │
│  - user_id (FK -> users)    │ │  - owner_id (FK -> users)   │
│  - crop_name, image_url     │ │  - machine_name, type, hp   │
│  - detected_disease         │ │  - price_per_hour, location │
│  - confidence, severity     │ └──────────────┬──────────────┘
│  - symptoms, advice (JSONB) │                │ 1:N
└─────────────────────────────┘                ▼
                                ┌─────────────────────────────┐
┌─────────────────────────────┐ │      machinery_bookings     │
│       weather_checks        │ │  - id (UUID PK)             │
│  - id (UUID PK)             │ │  - machinery_id (FK)        │
│  - crop_name, location      │ │  - farmer_id (FK -> users)  │
│  - temp, humidity, rain %   │ │  - booking_date, duration   │
│  - risk_level, concern      │ │  - estimated_cost, status   │

```

## 3. User Data Model (`users`)

Stores authentication credentials, persona classification, and location profiles:

| Field | Type | Constraint | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` / `VARCHAR` | Primary Key | Unique user identifier (`usr-...`) |
| `name` | `VARCHAR(150)` | NOT NULL | User's full name |
| `phone` | `VARCHAR(20)` | NOT NULL, UNIQUE | 10-digit mobile number |
| `email` | `VARCHAR(150)` | NOT NULL, UNIQUE | User email address |
| `password_hash` | `VARCHAR(256)` | NOT NULL | Salted SHA-256 password hash |
| `role` | `VARCHAR(30)` | NOT NULL | `'farmer'`, `'machine_owner'`, `'admin'` |
| `user_type` | `VARCHAR(50)` | NOT NULL | Display role label (`Farmer`, `Machinery Owner`, `Admin`) |
| `state` & `district` | `VARCHAR(100)`| NOT NULL | Farming location profile |
| `status` | `VARCHAR(20)` | DEFAULT `'Active'`| `'Active'` or `'Disabled'` |
| `created_at` | `TIMESTAMP` | DEFAULT `NOW()` | Registration timestamp |

## 4. Farmer Profile Data

Farmers maintain operational associations with:
- **Scan History**: Linked via `user_id` to past disease detections.
- **Weather Inquiries**: Cached weather risk queries for their registered state and district.
- **Machinery Bookings**: All active and past equipment rental reservations.

---

## 5. Disease Scan & Analysis Data (`disease_scans`)

Records visual pathology results generated by the Gemini Multimodal Vision engine:

- **`id`** (`UUID PK`): Unique scan record ID (`scn-gemini-...`).
- **`user_id`** (`UUID FK, Nullable`): Associated farmer ID.
- **`crop_name`** (`VARCHAR(100)`): Identified or selected crop species (*Tomato, Potato, Rice, Wheat, Cotton, Corn*).
- **`detected_disease`** (`VARCHAR(150)`): Diagnosed pathology or `"Healthy"`.
- **`scientific_name`** (`VARCHAR(150)`): Biological causal organism.
- **`confidence`** (`NUMERIC(5,2)`): Visual likelihood percentage.
- **`severity`** (`VARCHAR(20)`): `'Low'`, `'Moderate'`, `'High'`, `'Severe'`, `'None'`.
- **`symptoms`** (`JSONB`): Array of observable physical symptoms.
- **`advice`** (`JSONB`): Array of actionable curative steps and dosages.
- **`prevention`** (`JSONB`): Cultural farming practices.
- **`regional_explanation`** (`TEXT`): Hindi summary (*किसान सलाह*).

---

## 6. Weather Data Handling (`weather_checks`)

Stores crop-specific risk assessment snapshots:

- **`id`** (`UUID PK`): Unique log entry.
- **`crop_name`** & **`location`**: Evaluated crop and district name.
- **`temperature`**, **`humidity`**, **`rain_chance`**: Ingested Open-Meteo readings.
- **`risk_level`**: `'LOW'`, `'MODERATE'`, `'HIGH'`, `'CRITICAL'`.
- **`concern`** & **`recommendation`**: Actionable agronomic field guidance and spray suitability.

---

## 7. Machinery Data & Booking Records

### `machinery` (Equipment Listings)
- **`id`** (`UUID PK`): Listing ID (`eq-101`, `eq-102`, etc.).
- **`owner_name`**, **`owner_phone`**, **`owner_id`**: Equipment owner contact details.
- **`machine_name`** & **`machine_type`**: Brand/model and category (*Tractor, Harvester, Rotavator, Cultivator, Seed Drill*).
- **`horse_power`** (`INT`): Engine power rating.
- **`price_per_hour`** & **`price_per_day`**: Rental rates in ₹.
- **`rating`** & **`reviews_count`**: Aggregate feedback score.
- **`location`** & **`distance_km`**: Proximity indicator.
- **`features`** (`JSONB`): Array of feature tags (*Power Steering, 4WD, Rotavator Ready*).

### `machinery_bookings` (Rental Requests)
- **`id`** (`UUID PK`): Unique booking ID (`bk-...`).
- **`machinery_id`** (`UUID FK`): Reference to machinery listing.
- **`farmer_id`**, **`farmer_name`**, **`phone`**: Client details.
- **`service_location`**: Destination farm plot address.
- **`booking_date`** & **`start_time`**: Scheduled service timing.
- **`estimated_hours`** & **`estimated_cost`**: Server-verified duration and cost.
- **`status`**: Deterministic state (`'PENDING'`, `'ACCEPTED'`, `'REJECTED'`, `'COMPLETED'`, `'CANCELLED'`).

---

## 8. Market Intelligence Data (`market_prices`)

- **`crop_name`** & **`mandi_name`**: Agricultural commodity and target APMC market center.
- **`location`**: State/district of the mandi hub.
- **`price_per_quintal`** (`NUMERIC(10,2)`): Modal spot trading price in ₹/quintal.
- **`price_date`** (`DATE`): Trading date observation.
- **`source`** (`VARCHAR(100)`): Origin data provider flag.

---

## 9. Admin & Role Data

The database supports 3 roles with strict permission boundaries:
- **`farmer`**: Consumer of disease, weather, booking, and market services.
- **`machine_owner`**: Provider of machinery listings and receiver of booking requests.
- **`admin`**: System administrator with permissions to inspect all user accounts, toggle user active/disabled status, and moderate listings.

## 11. Primary Keys & Integrity Constraints

1. **UUID Primary Keys**: All entities use UUID / unique prefixed strings (`usr-...`, `eq-...`, `bk-...`, `scn-...`) preventing ID collision.
2. **Foreign Key Integrity**: `machinery_bookings.machinery_id` cascades on listing deletion.
3. **Check Constraints**:
   - `confidence BETWEEN 0 AND 100`
   - `price_per_hour > 0`
   - `estimated_hours > 0`
   - `status IN ('PENDING', 'ACCEPTED', 'REJECTED', 'COMPLETED', 'CANCELLED')`

## 12. End-to-End Data Flow

```text
React Frontend (Component State / Form Data)
                     │
                     ▼

                     │
                     ▼

                     │
                     ▼
Business Service Layer (backend/services/)
  - gemini_disease_service, weather_service, machinery_service, auth_service
                     │
                     ▼
Data Layer (backend/models/__init__.py)
  - If SUPABASE_URL + KEY present: executes PostgreSQL query via Supabase Client

                     │
                     ▼
Standardized JSON Envelope (success_response / error_response)
                     │
                     ▼
React Frontend Updates UI & Notification Counters
```

## 13. Supabase Integration: Live vs. Demo Mode

- **Connection Initializer (`backend/models/__init__.py`)**:
  ```python
  if SUPABASE_URL and SUPABASE_KEY and not SUPABASE_URL.startswith("https://your-project"):
      supabase_client = create_client(SUPABASE_URL, SUPABASE_KEY)
      is_database_configured = True
  else:
      print("[Supabase] Running in local demo mode with in-memory stores.")
  ```
- **Health Check Status**: `GET /api/health` accurately reports `database_configured: true` only when valid Supabase credentials exist in `backend/.env`.

## 14. In-Memory Fallback Behavior

During local hackathon evaluations where no cloud database is attached:
- **`USERS_STORE`**: Pre-seeded with demo Farmer, Machinery Owner, and Admin profiles.
- **`MACHINERY_STORE`**: Pre-seeded with 8 realistic Indian tractor and harvester listings.
- **`BOOKINGS_STORE`**: Maintains booking state transitions (`PENDING` $\rightarrow$ `ACCEPTED`) in memory throughout the server session.
- **`localStorage`**: Maintains in-app notification records and authentication tokens in the browser.

---

## 15. Authentication Data Handling

- Passwords are **never stored in plaintext**.
- The service hashes input credentials using salted SHA-256 (`_hash_password()`).
- All API responses pass through `_sanitize_user()`, which strips `password_hash` prior to transmission.
- Unique session tokens (`demo-tok-...`) map active sessions to user IDs.

---

## 16. Security & Secret Management

- **Environment Isolation**: Database keys (`SUPABASE_URL`, `SUPABASE_KEY`), Gemini keys (`GEMINI_API_KEY`), and port settings reside strictly in `backend/.env`.
- **Zero Client Exposure**: Frontend bundles never contain database service keys.
- **Public Templates**: `backend/.env.example` and root `.env.example` contain only placeholder documentation.

## 17. Production Migration Path

Migrating from the current hackathon demo to production persistence requires only two operational steps:
1. **Execute Schema**: Run [`database/schema.sql`](file:///c:/Users/preeb/agro%20smart%20tejas%20hackathon/database/schema.sql) and [`database/seed.sql`](file:///c:/Users/preeb/agro%20smart%20tejas%20hackathon/database/seed.sql) in the Supabase SQL Editor.
2. **Update Environment**: Paste your production `SUPABASE_URL` and `SUPABASE_KEY` into `backend/.env`.
*Zero Python route controllers or React components need to be modified.*

## 18. Scalability Architecture

To scale the data layer to millions of farmers:
- **Connection Pooling**: Use Supabase PgBouncer (Transaction mode) for high-concurrency connection handling.
- **Read Replicas & Indexing**: Add B-Tree indexes on `crop_name`, `booking_date`, and `user_id`, with PostGIS spatial indexing on `machinery (latitude, longitude)` for instant radius proximity queries.
- **Redis Caching**: Cache repetitive APMC mandi prices and Open-Meteo weather forecasts for 1 hour to reduce external API overhead.
